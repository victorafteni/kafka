Cele mai importante comenzi Git pentru un flux de lucru zilnic includ iniţializarea proiectelor, salvarea modificărilor şi sincronizarea cu serverul.
Inițializare și configurare
git init – Creează un depozit (repository) Git nou în folderul curent.
git clone <url> – Descarcă o copie a unui proiect existent de pe un server (cum ar fi GitHub). [1]
Salvarea modificărilor (Staging & Commit)
git status – Arată starea fișierelor (modificate, adăugate în staging sau neurmărite).
git add <fișier> – Pregătește fișierele modificate pentru a fi salvate (le mută în zona de staging).
git commit -m "mesaj" – Salvează definitiv modificările pregătite, sub forma unui punct de control (instantaneu). [1, 2]
Lucrul cu Branch-uri (Ramuri)
git branch – Afișează toate ramurile existente în proiect.
git checkout -b <nume> sau git switch -c <nume> – Creează o ramură nouă și comută imediat pe ea.
git merge <nume> – Combină modificările dintr-o ramură în ramura curentă. [1]
Sincronizare (Remote)
git pull – Descarcă și aplică ultimele modificări de pe serverul la distanță în proiectul tău local.
git push – Trimite modificările tale locale pe serverul la distanță. [1]

==================================================

Un flux de lucru complet și standard în Git (folosit pe scară largă în echipele de dezvoltare) se bazează pe conceptul de Feature Branching (crearea unei ramuri separate pentru fiecare funcționalitate nouă). Acest proces asigură că codul principal rămâne mereu stabil și funcțional.
Iată pașii exacți, de la preluarea proiectului până la publicarea modificărilor:
1. Sincronizarea inițială
Înainte de a începe lucrul, asigură-te că ai ultima versiune a codului de pe server.
git checkout main (sau master) – Comuți pe ramura principală.
git pull origin main – Descarci ultimele modificări făcute de colegi.
2. Crearea unei ramuri noi (Feature Branch)
Nu lucra niciodată direct pe main. Creează o ramură dedicată task-ului tău.
git checkout -b feature/nume-task – Creează și te mută pe noua ramură (ex: feature/login-page).
3. Dezvoltarea și salvarea locală (Staging & Commit)
Pe măsură ce scrii cod și faci modificări în fișiere, salvează-ți progresul în pași mici și logici.
git status – Verifici ce fișiere ai modificat.
git add . – Adaugi toate fișierele modificate în zona de așteptare (staging).
git commit -m "Adauga campul de email in formularul de login" – Salvezi un istoric local cu un mesaj clar.
4. Actualizarea ramurii înainte de publicare
În timp ce tu ai lucrat, colegii tăi au adus modificări pe main. Este recomandat să aduci acele modificări și pe ramura ta pentru a evita conflictele mai târziu.
git fetch origin – Descarcă informațiile noi de pe server fără să modifice codul tău.
git merge origin/main – Combină modificările noi din main în ramura ta curentă. Dacă apar conflicte, le rezolvi acum.
5. Publicarea codului pe server (Push)
Trimite ramura ta locală pe serverul la distanță (GitHub, GitLab, Bitbucket).
git push origin feature/nume-task – Încarcă ramura ta pe server.
6. Finalizarea (Pull Request & Merge)
Deschizi un Pull Request (PR) sau Merge Request în interfața web (GitHub/GitLab).
Colegii tăi îți revizuiesc codul (Code Review).
După aprobare, se dă Merge, iar codul tău ajunge în ramura principală main.
git branch -d feature/nume-task – Ștergi ramura locală care nu mai este necesară.

For each feature to be developed create a branch starting from the master branch (git checkout –b feature/JIRA_PROJECT_NAME-TASK_ID). For e.g.: git checkout –b feature/PROACT-10.
Make changes to current feature branch.
Whenever you are ready to commit these changes, run the git status command to check which files were changed.
From the list of changed files choose the ones you want to commit. Run git add file_name command to add each file/folder that you want to add to the commit.
When all files are added, run the git commit –m “JIRA_PROJECT_NAME-TASK_ID commit message” command. Sample command: git commit –m “PROACT-10 added new entity and created service in order to access the given data”
Send the changes to remote:
                                                     i.     If this is the first push, run the command git push origin –set-upstream feature/JIRA_PROJECT_NAME-TASK_ID (for e.g. : git push origin –set-upstream feature/PROACT-10)

                                                   ii.     If this is not the first push, run the command git push

Create a Bitbucket pull request to merge the feature branch into the master branch (http://86.120.120.41:8001/projects/PROACT/repos/back-end-gestiune/pull-requests top right corner).
Solve/discuss all the review comments. Make changes on the feature branch and then push the changes remote (repeat step 1.e.ii )
After the request is approved by 2 more colleagues do the following:
Squash the commits in the feature branch (git rebase -i HEAD~n, where n is the number of commits on feature branch – you can find the number of commits on this particular branch by running git log command and checking the number of commits)
Update the master branch to have the latest changes (git checkout master + git pull)
Rebase the feature branch to master (git rebase master on the feature branch)
Fix conflicts locally (in case there are any files in conflict when doing "git rebase master" do the following: manually merge the files in conflict in Eclipse IDE, save the files in IDE, type in "git add "FILE_IN_CONFLICT_NAME" " for each file which was in conflict and the run the "git rebase --continue" command. In case the merge did not go as planned and you need to start over after the above step c) you can run "git rebase --abort" and start over. DO NOT run "git rebase --skip" as this will only move the code from master branch into your feature branch and you will loose all the work on the feature branch. If "git rebase --skip" was run by mistake DO NOT push the changes. Instead delete the local feature branch and then checkout from remote again).
Push changes (force push to remote branch) (git push origin +branch_name for e.g. git push origin +feature/PROACT-10)
Merge feature branch into master branch from Bitbucket pull request
Delete the local feature branch using the command git branch –D feature/JIRA_PROJECT_NAME-TASK_ID (for e.g. git branch –D feature/PROACT-10)master
