# Kafka Integration & Event Streaming

## 1. Overview

Apache Kafka is used as the event streaming backbone for user activity and telemetry tracking. The system ingests navigation events from the Angular single-page application and decouples ingestion from consumer processing.

---

## 2. Topics & Consumer Group Configuration

| Entity | Name | Description |
|---|---|---|
| **Primary Topic** | `shop.analytics.page_views` | High-throughput topic for user page navigation events (3 partitions) |
| **Dead Letter Queue** | `shop.analytics.page_views.dlq` | Fallback topic for unparseable or repeatedly failing messages |
| **Consumer Group** | `shop-analytics-consumer` | Consumer group that tracks message offsets independently |

---

## 3. Producer Architecture (`KafkaService`)

- **Singleton Pattern**: A single reusable `Producer` instance is maintained throughout the lifetime of the Express process.
- **Connection Recovery**: Automatic reconnect with exponential backoff.
- **Partition Key**: Events are keyed by `session_id` (or `user_id`) to ensure that all navigation events for a given user session land on the same partition in sequential order.

---

## 4. Consumer Architecture (`AnalyticsConsumer`)

- **Group Id**: `shop-analytics-consumer`
- **Offset Management**: Automatic offset commits upon successful processing of message batches.
- **Idempotency**: 
  - Every event carries a unique `event_id` UUID generated by the backend.
  - The consumer tracks processed IDs to detect and discard duplicates before applying business logic.
- **Retry & DLQ Routing**:
  - If event processing throws an exception, the consumer attempts an automated retry.
  - If the retry exceeds the threshold (e.g. 2 attempts) or the payload is invalid JSON, the event is packaged with error metadata and published to `shop.analytics.page_views.dlq`.

---

## 5. Visual Inspection with Kafka UI

The Kafka UI is running on port `8085`:

👉 **[http://localhost:8085](http://localhost:8085)**

Steps to view messages in Kafka UI:
1. Open [http://localhost:8085](http://localhost:8085).
2. Go to **Topics** in the left sidebar.
3. Click on **`shop.analytics.page_views`**.
4. Click on the **Messages** tab.
5. In the **Seek Type** dropdown, select **`Beginning`** (or enter offset `0`) and click **Submit**.
6. You will see every `page_view` event with headers, partition numbers, and complete JSON envelope.
